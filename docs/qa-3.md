## Findings
### BLOCKER
None.
### MAJOR
**M1. A late save result lands on the wrong screen, so a later save can go to the wrong draft.** `components/app/Composer.js:270-282` (`save`), `:332-358` (`saveSteps`), `:361-380` (`saveAsNew`). None of them checks whether the person moved on while the save was in flight; `requestId` (used for the AI answer) is not used here. Reproduced twice in the harness (`run-b3.mjs`):
(a) Open Draft One, edit, press Save changes, and while it saves open Draft Two and press Discard. When the save returns, the box shows Draft Two's request but the plan is Draft One's edited steps, headed "Saved plan", status "Draft updated". Edit steps then Save changes wrote into **Draft One** while the person believes they are on Draft Two.
(b) Press Save as draft on an unedited preview and open another draft at once (no question is asked, nothing is unsaved). After the save, the screen shows the opened draft with the NEW draft's id attached; Edit steps then Save changes overwrote the new draft's plan with the other draft's steps (row "Brand new request" got "TWO PLAN EDIT").
Window: one server round trip, or up to 15 s when the Server Action waits behind an abandoned AI call (README AI note). Fix: in all three functions `const mine = requestId.current;` before `startSaving`, and after each `await` `if (mine !== requestId.current) return;` before any `setPlan/setDraft/setSaveState/closeEditor` (the counter already goes up in `reset` and for every new seed, so opening anything else cancels the result; the server write still happened, which is correct). Add a harness or source test if wanted.
### MINOR
**m1. Lost update in the read-then-write gap (documented, accepted).** `lib/update-plan.js:36-54`. Reproduced with the fake client: another tab's write between the read and the write is overwritten and our save answers ok. The README sentence is true and the failure is no worse than that (only the `plan` column; other users untouched; a delete in the gap gives `gone`; a rename in the gap is not lost). One inaccuracy: README says closing it "needs a database function". It does not: add `.eq("updated_at", current.updated_at)` (the text just read, never the browser's) to the update and treat 0 rows as `changed` after one re-read. No schema change. Only the owner can prove the filter matches the live table, so do it together with the owner's step 3/7, or leave as is.
**m2. One tab is enough for a false conflict.** `Composer.js:341` with `DraftCard` rename. Open a draft, rename it in the list, Edit steps, Save changes: "This draft was changed somewhere else..." (reproduced, `B2b`). README says "in another tab" and "nothing is lost", but the only ways out are Load latest (throws the typing away) or retyping. Fix: in `saveSteps`, when `result.why === "changed"` and `sameSteps(result.latest.plan, steps)` (stored steps are still the ones I started from, so only the name moved), set `draft` to `{ ...draft, name: result.latest.name, version: result.latest.version }` and run the save once more. Reword the README line.
**m3. Leaving through the sidebar loses edits without a question.** `AppNav.js:75` ("Runs"), the logo, browser Back. `beforeunload` does not fire for in-app navigation. README says so; the screen does not. Not run (needs sign-in). Owner decision: add the click guard from `docs/design-editor.md` 1.4, or one line in the editor hint ("Leaving this page, including the Runs link, loses unsaved steps").
**m4. Three test gaps** (`lib/update-plan.test.js`): assert `userId` in `drafts.js` is exactly `user.id` (M20); assert `saveDraft` returns `version` (M27, e.g. a source check like the existing ones); assert error answers carry no `ok` key (M31).
### NIT
n1. `lib/validate.js:89,125`: invisible-only titles pass "needs a title" and show a blank row: U+200E, U+200F, U+061C (direction marks, the same family the code says it removes), U+2060, U+00AD, U+3164, U+2800, U+FE0F. Add them to the strip class.
n2. `lib/validate.js:89` and 14 test lines hold LITERAL invisible characters inside the regex and strings. A beginner cannot see or safely edit them, and a "clean whitespace" action in an editor can delete them. Use `​-‍﻿‪-‮⁦-⁩` as `checkPrompt` (line 74) does; one list serves both functions.
n3. `lib/update-plan.js:15` `plainSteps` is exported but only used inside; `StepEditor.js:31` repeats `knownIcon` from `validate.js:95`.
n4. `lib/actions/drafts.js:16` header says every action returns `{ ok: true }` or `{ error }`; `saveDraft`/`updateDraft` now return more.
n5. `app/privacy/page.js:36` "It reaches our server only if you press Save as draft." The editor adds "Save as new draft" (also sends the request text) and "Save changes" (sends the steps). Add "or Save as new draft". The plan said `/privacy` needs no change; this one clause does.
n6. `Composer.js` `preview()` leaves `editing` true when the arrow is pressed with an unchanged editor open; if the server ever answered `{error}` the request box would stay locked with no editor on screen (see E2b). Unreachable today (`{error}` only for empty or over-long text). Fix: `setEditing(false)` at the top of `preview()`.
n7. `docs/plan-editor.md` describes the first design (update filtered by `updated_at`, `{ok:true}` return, `<select>`, editor inside the card); the build differs. Add a "built differently" note at the top so the owner is not misled.
n8. Two `role="status"` elements exist (the hidden one and the card's "Not saved yet."/"Saved..." line). They mount at different times, so double speech is unlikely, but only a screen reader can tell (owner step 9).
n9. `Composer.js` is 595 lines with about 20 `useState` calls (AI, saving and step editing together). Fine today; if it grows, move the editing state into one small hook.

## Needs the owner to test

1. Open `/app`, type a recipe, press the arrow, press **Edit steps**, change a title and an icon, press **Done**, then **Save as draft**. Reload: open the draft from the list; your edited steps are there.

6. **Rename then edit (m2):** open a draft, rename it in the list, then Edit steps and Save changes. Today you get the conflict message; after the m2 fix you should not.

8. **Unload prompt:** type in the editor and reload or close the tab: the browser asks "Leave site?". Click "Runs" in the sidebar with unsaved steps: nothing asks (m3).
